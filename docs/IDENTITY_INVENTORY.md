# Read-only production identity review

Issue #9 is the coordination record. This workflow is prepared for review only: **obtain explicit owner approval before dispatching it against production or exposing private details**. Merging a draft does not supply that approval. No new secret or permission is required. The daily schedule, encrypted state, Google federation and document publisher are unchanged.

## Browser-only review

1. An authorized scientific reviewer downloads `tools/inventory-reviewer.html` from the reviewed commit and opens the local file in a modern browser. Disconnecting networking is recommended. Its content security policy blocks network requests. Click **Generate one-time recipient**; keep this tab open. The nonextractable private key stays in memory and is lost on reload/close. No `GLO_STATE_KEY` is entered or shared.
2. After approval and merge, select **Read-only identity inventory → Run workflow → main** in GitHub Actions. Paste only the public JWK from the browser into `recipient`. Never paste a private key or product data. Confirm the recipient was generated by the intended reviewer through a trusted channel; public-key substitution would expose the report to that key's holder.
3. The workflow restores the latest trusted daily-monitor artifact, with no seed fallback, and reads a temporary copy using SQLite read-only/immutable/query-only mode, without application migrations. It neither fetches sources nor authenticates to Google nor writes state back. Missing/expired/corrupt state fails closed. It shares the daily database concurrency group so it waits for ongoing daily monitoring.
4. Download and extract `glo-identity-inventory-RUN-ATTEMPT` from that run within **one day**. Only aggregate counts and encrypted detail are uploaded. In the original reviewer tab, select `inventory.enc.json`. Verify the displayed repository and session (`RUN-ATTEMPT`) against the approved run before using it. Wrong keys or modified ciphertext fail authentication. No report bytes are sent to a service by the reviewer page.
5. Review all records against primary identity references in an authorized private system. `identity_review_references` includes historical product audit entries, which may contain no identity verification. Source/guide references, raw heading and flags are retained for investigation. An `imported` or `reviewed` database label is **not** scientific approval; the export always requires review. Compound mapping is separate from vendor vial/batch contents, COA authenticity, safety and clinical claims. Semaglutide, tirzepatide and tesamorelin remain candidates until explicitly mapped by a named qualified reviewer.
6. Keep private mappings, source URLs, raw rows and detailed review notes out of public GitHub/chat. Record only aggregate progress and approval/blocker status there. Close the browser tab after review; delete downloaded ciphertext when no longer needed. GitHub retention is one day, not permanent backup. The workflow removes temporary output even on failure; restored plaintext exists only in an automatically deleted temporary directory on the ephemeral runner. Cancellation/runner termination relies on ephemeral runner disposal. No encrypted inventory replaces the production backup.

## Limits and next gates

Browser key loss requires a new approved run, never recovery through the repository symmetric key. The reviewer HTML is an offline local tool, not a hosted site; GitHub raw HTML preview will not execute it. A reviewer should use a trusted computer without browser extensions that can inspect local files. Synthetic encryption roundtrips do not establish live production access or a live browser acceptance test.

Next: private scientific identity mapping approval; separately reviewed additive research configuration (no secret changes without approval); the next eligible scheduled catalog attempt after cooldown (no forced retry); private source reliability/guide reconciliation plan. Original document or medical claims remain behind explicit approval. Do not claim the 46-entry inventory, production literature coverage, source recovery or final acceptance until observed and reviewed.
